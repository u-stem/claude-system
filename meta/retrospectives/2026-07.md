## failure-log.jsonl の繰り返しパターン

```
tools/loop-report.sh --project ~/ws/claude-system 実行結果(2026-07-08):
 -- failure-log --
  no data
```

**`failure-log.jsonl` はどのプロジェクトにも存在しない = 記録→検出のループは配備以来一度も発火していない**。解釈は 2 通りあり得る: ①記録対象の失敗(check / check-types / test カテゴリの exit≠0)が実際に発生していない ②`log-bash-failure.sh` のカテゴリ判定条件が実際の失敗コマンドにマッチしていない。②なら記録の段が壊れていることになる。次回失敗が起きた際に記録されるかを観測する(意図的にテスト失敗を起こして確認するのも可)。

| カテゴリ | プロジェクト | 出現数 | 推測される原因 |
|---|---|---|---|
| (no data) | 全 12 プロジェクト | 0 | 上記 ①/② 未切り分け |

### 計測所見(loop-report.sh 初回実行)

- `subagent-log.jsonl`(claude-system): 155 件(2026-04: 1 / 05: 46 / 06: 77 / 07: 31)。exit_code≠0 は 0 件
- **agent_type 空率: 全期間 71.0%(110/155)、2026-06 以降 64%、2026-07 以降 74%(23/31)** — ADR 0012 Update(2026-06-05、当時 69%)の sidecar backfill 対処後も改善していない。当初仮説は「対処が機能していない」だったが、同日の切り分けで**空 = Agent ツール起動でないハーネス内部の補助エージェント**(per-agent transcript / meta.json がディスクに無い)と確定。ユーザー起動の委譲は 7/7 全件型付き記録されており、hook は壊れていなかった(分母の汚染)。修正後は内部分が `"(internal)"` と明示記録される
- model 空率: 51.0%(79/155)。切り分けの副産物として、**空でない model 値も誤帰属**(payload の transcript_path はメインセッションを指すため、メインの model を記録していた)と判明。過去レコードの model 列はロール別評価に使えない(修正後の前進記録から有効)。model 語彙の揺れ(`opus` エイリアスと full ID の混在)も同根で、修正後は per-agent transcript の実 ID に統一される
