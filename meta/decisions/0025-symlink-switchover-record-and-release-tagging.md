# ADR 0025: symlink 切り替えの記録と、ADR 0005 が約束した成果物の決着

- **Status**: Accepted
- **Date**: 2026-08-09
- **Decider**: リポジトリオーナー(ADR 0001 の識別子規約に従う)

## Context

[ADR 0005](./0005-bootstrap-completion-and-deferral.md) は「切り替え後のリリース」節(66-70 行)で、Phase 10 完了時に 3 つを行うと明文で約束していた:

1. ADR `0006-symlink-switchover.md` の起票(切り替え日時 / 動作確認結果 / バックアップ場所)
2. `git tag v0.1.0`(正式リリース)
3. 旧 claude-settings の GitHub 側 archive 設定の再確認

**切り替え自体は 2026-05-04 16:25 に完了した**([`meta/CHANGELOG.md`](../CHANGELOG.md) の「Phase 10: 旧設定からの移行」)。しかし約束された成果物のうち 1 と 2 は履行されなかった:

- `0006` 番は**同じ 2026-04-29 に別テーマ**([No User Identifiers Inside the System](./0006-no-user-identifiers-in-system.md))へ採番された。切り替え ADR の予約番号だったことは、採番時に参照されなかった
- タグは `v0.1.0-rc1` / `v0.1.0-rc2`(ともに 2026-04-29)で止まり、`v0.1.0` は未発行
- 一方 `VERSION` ファイルは bootstrap 以来 `0.1.0` のまま一度も変更されていない。ファイルとタグが 3 か月ずれていた

この未履行は **2026-08-09 の棚卸しで初めて発見された**。`meta/TODO-for-v0.2.md` にも載っておらず、3 か月間どの検査にもかからなかった。

### 構造的原因(本 ADR の主要な記録)

これは単なる失念ではなく、**ADR の役割の取り違え**である。

ADR は「なぜそう決めたか」の記録であり、実行待ちタスクの置き場ではない。0005 は判断の記録に「完了時にこれをやる」という**未来の実行の約束**を混ぜた。その結果:

- 約束はどの機械検査の対象にもならなかった(`doctor.sh` は draft のプレースホルダは見るが、確定 ADR の本文に書かれた約束は読まない)
- TODO ファイルへの転記もされなかったため、棚卸しの視野にも入らなかった
- Phase 10 を実行したセッションは、切り替えの完了報告はしたが、0005 が別途約束していた後続成果物までは追跡しなかった

**約束を書いた場所と、約束を回収する仕組みが接続されていなかった。** 同じ形の負債(実行はされたが記録に反映されない)が Phase 10 完了の文書反映 17 箇所でも起きており、根は共通している。

## Decision

### 1. 切り替えの記録は本 ADR で果たす(番号は繰り上げる)

`0006` を切り替え ADR にリネームすることはしない。既に多数の文書から参照されており、`meta/decisions/README.md` の「欠番禁止 / 番号の削除はしない」に反する。0005 が予約した番号は失われたものとして扱い、記録は本 ADR が引き継ぐ。

**切り替えの実施記録**(0005 が求めた内容):

| 項目 | 実績 |
|---|---|
| 実行日時 | 2026-05-04 16:25 |
| 実行手段 | `tools/migrate/from-claude-settings.sh`(手動リトライで完了 / ADR 0007) |
| 対象 | `~/.claude/` の `CLAUDE.md` / `skills` / `hooks` / `commands` / `agents` を claude-system 配下への symlink 化 |
| `settings.json` | cp 配置。以降 [ADR 0017](./0017-settings-auto-sync.md) の `tools/sync-settings.sh` がレンダリングを所有 |
| バックアップ | `~/.claude-system-backups/migration-<TIMESTAMP>/`(永続保管、`cleanup-backups.sh` の対象外) |
| 動作確認 | `tools/doctor.sh` clean。以降 3 か月の実運用で hooks の発火を継続確認(ADR 0020 / 0023 / 0024 が実データで裏付け) |
| 実行中の観測 | 2 件を [ADR 0007](./0007-phase10-migration-script-robustness-and-boundary.md) に記録済み |

0005 の完了条件 5 項目はすべて充足している。

### 2. `git tag v0.1.0` は運用者の明示判断に委ねる

タグの発行は push を伴う**不可逆・外向き操作**であり、[ADR 0009](./0009-opus-48-autonomy-tuning.md) の線引き(可逆=自律 / 不可逆・外向き=確認)に照らして、棚卸し作業の一環として自動的に打つべきものではない。

判断材料:

- 切り替えは 3 か月前に完了し、0005 が定めた「問題なく数日運用できれば」の条件は十分に満たされている
- 一方、タグを打つ時点の HEAD は bootstrap 完了時点から大きく先行しており、`v0.1.0` が指す内容は 0005 の想定(切り替え直後の状態)とは別物になる
- 遡って 2026-05-04 のコミットに打つ選択肢もある

**本 ADR ではタグを発行しない。** README のバージョン表には「未発行」と事実を記載した。運用者が発行を決めた時点で本 ADR に `## Update` を追記する。

### 3. 旧 claude-settings の archive 確認は Private 側の作業として扱う

0005 の 3 番目の約束は Private リポジトリの GitHub 設定であり、Public な本リポジトリの成果物ではない([ADR 0002](./0002-public-private-boundary.md))。本 ADR では「Public 側から確認・記録する対象ではない」と整理し、以後この項目を claude-system の未消化事項として数えない。

### 4. 再発防止 — ADR に未来の実行を約束するときの規約

`meta/decisions/README.md` の「ADR を書くタイミング」に、次を追加する:

> ADR 本文に「後でこれを行う」と書く場合、同じコミットで `meta/TODO-for-v0.2.md`(または後継の TODO ファイル)へ転記する。ADR は判断の記録であって実行待ちタスクの置き場ではない。転記しない約束は履行されないものとして扱う。

機械側の担保は本 ADR では作らない。ADR 本文から「約束文」を自然言語で検出する検査は誤検出が避けられず、[principles/06](../../principles/06-evolution-strategy.md) の「機械的に防げる事故」の範囲を超える。転記されたあとの TODO は棚卸しの対象になるため、接続点は転記の一箇所で足りる。

## Alternatives Considered

| 案 | 採否 | 理由 |
|---|---|---|
| `0006` を切り替え ADR にリネームし、既存 0006 を末尾に採番し直す | 不採用 | 番号の付け替えは `meta/decisions/README.md` の「古い番号の削除はしない」に正面から反する。0006 は CHANGELOG / ADR 0008 / user-level CLAUDE.md など多数から参照されており、参照切れの害が記録の整然さを上回る |
| 本 ADR を書かず、0005 に `## Update` を足すだけで済ませる | 不採用 | 切り替えの実施記録が ADR 層に存在しない状態が残る。CHANGELOG には記録があるが、0005 が「ADR として残す」と判断した対象であり、その判断自体を覆すなら理由の記録が要る |
| `git tag v0.1.0` を本作業で発行する | 不採用(保留) | 不可逆・外向き操作。ADR 0009 の線引きにより運用者の明示判断を待つ |
| 約束の未履行を機械検出する検査を作る | 不採用 | ADR 本文の自然言語から「約束」を判定する検査は誤検出が避けられない。転記規約(§4)で接続点を人間側に一本化するほうが確実 |

## Consequences

- **Positive**: 3 か月宙吊りだった 0005 の約束が決着した。切り替えの実施記録が ADR 層に残り、`0006` 番の衝突経緯も追跡可能になった。ADR に未来の実行を書くときの規約ができ、同型の失念に接続点ができた
- **Negative**: `v0.1.0` は依然未発行で、`VERSION` ファイル(`0.1.0`)とタグの乖離は解消していない。運用者の判断を待つ間、この不整合は残る
- **Neutral**: 0005 の Status は `Accepted` のまま変えない。その判断(rc1 で一旦止めて切り替えを別セッションに送る)自体は正しく、覆されてもいない。変わったのは約束の履行状況だけであり、それは `## Update` で表す
